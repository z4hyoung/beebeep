## 核心手法：stub/include-path，一行没改 source/src

`INCLUDEPATH` 把 `android/ybcore/stubs` 放**最前**，同名头优先命中 stub：

1. **Config.h 是总闸门**：`src/core/Config.h` 无条件 `#include <QtWidgets> <QtMultimedia> <QtPrintSupport>`。因为 .pro 里没加这三个模块，Qt 的 include 路径里根本没有它们 → 在 stubs/ 放**无扩展名同名文件** `QtWidgets`/`QtMultimedia`/`QtPrintSupport` 即可拦下（stubs/QtWidgets 再转 include 具体类 stub）。
2. **QApplication 是个深坑**：Settings.cpp/BeeUtils.cpp/Avatar.cpp 用 `QApplication::font()/applicationDirPath()`、`qApp->translate()/applicationFilePath()/palette()`，BtManager.cpp 还用 `qApp->checkPermission()/requestPermission()`（Qt6.5+ 权限 API，Android 蓝牙真的会走到）。解法：stub 的 `class QApplication : public QCoreApplication`，`#define qApp (static_cast<QApplication*>(QCoreApplication::instance()))`（仿 Qt 原定义）——实例侧 API（translate/权限/applicationFilePath）落到真 QCoreApplication 上照常工作，font/palette 返回默认值。QtGui 的 qguiapplication.h 本身也定义 qApp，会有一条 "-Wmacro-redefined" 警告，**benign**（我们的定义在后，稳定胜出）。
3. **BeeUtils.cpp 拖了三个 widget 类**：`QComboBox`（comboBoxData/selectComboBoxData，仅 voicechat 用）、`QWidget`（showUp/raiseOnTop/setWindowStaysOnTop/setBackgroundColor）、`QColorDialog::getColor`。全部做成 no-op stub 类挂进 stubs/QtWidgets 伞。
4. **BeeApplication stub**：QObject 子类，只实现 core 用到的 addJob/removeJob/setSettingsFilePath/setCheckSettingsFilePath；**不给 beeApp 宏**，改为 `extern BeeApplication* beeApp` 全局指针（BeeApplication_stub.cpp 里 `BeeApplication bee_app_instance; BeeApplication* beeApp = &bee_app_instance;`），core 里的 `if(beeApp)`/`beeApp->addJob(x)` 原样编过。
5. **Updater/GAnalytics stub**（带 Q_OBJECT，moc 正常生成）：Core.cpp 无条件 new 它们并按名字 invokeMethod("checkForNewVersion"/"doPost")，stub 立即 emit jobCompleted = "无更新/不上报"。HttpDownloader 因此完全不需要。
6. **GuiChatMessage stub**：ChatManager/SaveChatList 调 `chatToHtml()` 存聊天记录，真身在 desktop/（拖 YongTheme+QtSvg），stub 返回空串（Android 端存档暂为空文件，A1.3+ 壳层自己渲染）。
7. **AudioManager stub**：isAudioDeviceAvailable()=false、play/clear 全 no-op，类布局对齐原头（voice-chat 段自然消失，因为 BEEBEEP_USE_VOICE_CHAT 未定义）。

## 踩坑记录

1. **qmake 的 INCLUDEPATH 顺序**：project 目录/-I./INCLUDEPATH 都排在 Qt 模块 include **之前**（见 a0-smoke Makefile 的 INCPATH），所以 stubs 放第一个 INCLUDEPATH 条目即可稳定压制 source/src 同名头；与 Qt 本体无冲突（被 stub 的模块名根本不在 Qt include 路径里）。
2. **`$$PWD/../../...` 相对路径**在 qmake 里要用 `$$clean_path()` 归一（否则 warning/重复分隔符）。
3. nm 验证时**手数 mangled 长度前缀容易错**（BtManager=9、FileTransfer=12、EmoticonManager=15，不是 8/11/9）；grep 计数为 0 先怀疑前缀再怀疑链接。
4. android-clang 的 CXXFLAGS **不含 -fvisibility=hidden**，全部符号默认导出，`llvm-nm -D` 直接可见，不用额外加导出脚本。
5. BtWinWorker.cpp 整文件 `#if defined(Q_OS_WIN)` 包裹，Android 下编成空 TU，clang 接受；MinGW 构建不受影响（stub 只存在于 android/ybcore 工程）。
6. utils/ 清单的取舍：BeeUtils **必须编**（core 全在用）；GAnalytics/HttpDownloader/Updater 按任务排除改走 stub（见上第 5 条）；SpellChecker*.cpp 本就未编（BEEBEEP_USE_HUNSPELL 未定义）。

- qApp 依赖宿主进程先建好 QCoreApplication（Qt for Android 加载 Qt 时自建）；stub 的 font/palette 是哑的，UI 侧配色自行处理。
- 聊天记录导出（chatToHtml）为空实现；如 Android 要存档，在壳层或届时引入 QtSvg 编真身。

## 踩坑记录（复现必读）

1. **Qt .so 的 JNI_OnLoad 有 Java 硬依赖**：`System.loadLibrary("Qt6Core_arm64-v8a")` 时 QtCore 的 JNI_OnLoad 会 `FindClass("org/qtproject/qt/android/QtNative")`，dex 里没有 → `initJNI failed` → JNI_ERR → UnsatisfiedLinkError。解法：把 Qt 安装目录 `jar/Qt6Android.jar` + `Qt6AndroidNetwork.jar` + `Qt6AndroidBluetooth.jar` 打进 APK（对应加载了哪些 Qt 模块就带哪些 jar）。
2. **Qt 安卓胶水的 context 注入**：不走 QtActivity/QtNative.startQtAndroidPlugin 时，`QNativeInterface::QAndroidApplication::context()` 为空 → QtBluetooth `getDefaultBluetoothAdapter()`（context.getSystemService）在 CheckJNI 下 `GetMethodID received NULL jclass` 直接 SIGABRT；且 QStandardPaths 安卓路径全空（Settings 落到 `/beebeep.ini` 不可写）。解法：`YbQtGlue.java` 放进 `org.qtproject.qt.android` 包内（同包才能调 package-private 的 `QtNative.setClassLoader/setActivity`），MainActivity.onCreate 先行调用。修复后 Settings 正确落到 `/data/user/0/com.yongbeep.app/files/beebeep.ini`。
3. **QFontDatabase 硬中止**：`Settings::Settings()→setChatFont(QApplication::font(),true)→QFontMetrics::height()` 触到 QFontDatabase，无 QGuiApplication（核心只建 QCoreApplication）→ `F Must construct a QGuiApplication` SIGABRT。解法：stubs 新增 `QFontMetrics`（YbStubFontMetrics：height=16/horizontalAdvance=8 + `#define QFontMetrics YbStubFontMetrics`），从 stubs/QtWidgets 伞 include。Config.h 里 `<QtGui>`（真伞，定义真类）在 `<QtWidgets>`（stub 伞）之前，宏只改写项目源码里的 QFontMetrics 记号，Qt 自带头已解析不受影响——副作用即 emoticon 尺寸用定值（chat 24/edit 16，与桌面默认一致）。
4. **QCoreApplication 不能建在 JNI 主线程**：Qt 警告 `QApplication was not created in the main() thread`（无害化处理：我们在专用 QThread 的 started 槽里创建，警告仍打一次但不影响）。安卓上 Qt 自己也是这么干的（QtNative.startQt 起 QtThread）。
5. 模拟器无蓝牙适配器：BluetoothManager.getSystemService 返回空 → `Platform does not support Bluetooth` 警告 → BtManager 优雅降级（A1 阶段本来 setUseBluetooth(false)），Core 构造不再崩。
6. adb 侧屏幕取词用 `uiautomator dump` + 正则抽 text 属性，Compose 文本可读（比 OCR 稳）；按钮坐标从 bounds 算中心。

## 遗留（给 A1.4）

- **LAN 互通未验**（无对端）：`nativeConnectPeer` 已通到 `Core::checkNetworkAddress`，A1.4 接 Mac 桌面端 YongBEEP（10.0.2.2:6475 或宿主机局域网 IP）验 message_received 真实闭环 + sendChatMessage 到默认聊天。
- `onCoreEvent` 实现为实例方法而非 @JvmStatic：C 侧持有 CoreBridge 单例 jobject 全局引用走 CallVoidMethod，语义等价（@JvmStatic 静态方法需 GetStaticMethodID+CallStaticVoidMethod 配套改）。

- 多轮 install 后模拟器时区/时间未校准不影响功能；`Broadcaster has received loopback datagram` 属预期（自环过滤）。
