# UI 技术路线决策：继续 Qt（自绘消息列表）vs 迁移 Flutter

| | |
|---|---|
| **日期** | 2026-11-04 晚（用户授权连续执行） |
| **决策** | ✅ **继续 Qt，消息列表升级为自绘（QListView+delegate）**；Flutter 列为"未来重写选项"，非本次迁移 |

## 一、结论先行

三个 UI 痛点（气泡边缘参差/宽度不自适应/Markdown）**全部源于 Qt 富文本（QTextBrowser+HTML）这条渲染路线的能力天花板**，而不是 Qt 框架本身。换到 Qt 自绘消息列表后三者同时解决；换 Flutter 则是推倒重来。

## 二、成本对比（诚实核算）

| 维度 | 继续 Qt + 自绘消息列表 | 迁移 Flutter |
|---|---|---|
| 蓝牙传输层 | **已完成并实测**（RFCOMM 扫描/监听/SDP 通过，LAN 互通验证） | 重写。pub.dev 2025-2026 出现了桌面经典蓝牙包（flutter_bluetooth_classic_serial / bluetooth_rfcomm / dart-bluetooth），但均为小社区维护、SDP 自定义服务/配对 UX/长期维护未经验证 |
| 协议栈（Message/FileChunk/ECDH/发现） | **已完成**（C++/Qt） | 全部用 Dart 重写（ECDH+AES、分块停等、防重链……） |
| UI | 三个痛点一次手术解决（本次任务） | 全部界面重做 |
| 工作量估计 | **2-4 天**（一个手术） | **3-5 周**（重写整个产品） |
| 风险 | 低（增量替换，失败可回退富文本路线） | 高（新栈+新蓝牙库双重新） |

## 三、自绘消息列表方案（本次实施）

- `QListView` + 自定义 `MessageDelegate`：QPainter 直接画**真圆角气泡**（路径圆角任意）、按 `QTextDocument::sizeForWidth()` 做**shrink-to-fit 宽度**（右侧不再大片空白）
- **Markdown**：Qt 内建 `QTextDocument::setMarkdown()`（qtgui 自带 md4c 解析器，官方安装包里早就有 libmd4c）——delegate 里对带 Markdown 标志的消息调 `setMarkdown`，其余照旧 `setHtml/setPlainText`
- 协议扩展（照抄 InlineFile 模式）：`Message::Flag` 尾部追加 `Markdown` 位；输入栏加 MD 开关
- 历史消息重载/实时追加/文件卡片/时间戳逻辑全部迁移到 model+delegate

## 四、Flutter 何时值得 revisit

若未来把 YongBEEP 当作新项目重写（UI 优先、功能全量重做、有 3-5 周预算），Flutter + 上述桌面经典蓝牙包可作候选；届时须先做蓝牙包的 PoC 验证（自定义 SDP UUID 服务注册、双平台吞吐）。

**Sources**: pub.dev 包信息（flutter_bluetooth_classic_serial v1.3.2 2025-05、bluetooth_rfcomm、dart-bluetooth、flutter_classic_bluetooth）来自 2026-11-04 检索。
